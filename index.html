What is a graph?

A graph G = (V, E) is a collection of vertices (also called nodes) V, connected by edges E that represent a relationship between pairs of vertices. Graphs are used to model networks — anything with "things" and "connections between things": cities and roads, people and friendships, web pages and hyperlinks, tasks and dependencies.

What is graph traversal?

Traversal means systematically visiting the vertices reachable from a chosen start node, typically so we can search, measure distance, or explore structure. The two fundamental traversal strategies are Breadth-First Search (BFS), which explores level-by-level outward from a start node, and Depth-First Search (DFS), which dives as deep as possible along one path before backtracking. Both guarantee that every reachable node is visited exactly once and never revisited — this is enforced with a visited set, which is also what makes both algorithms safe on graphs that contain cycles.

Head to the Visualizer tab to build a graph and watch both algorithms run step by step, or the Algorithms tab for pseudocode and complexity analysis.

    BFS & DFS, explained

    BREADTH-FIRST SEARCH

    Level by level, using a queue

    BFS starts at a source node and explores all of its direct neighbors first, before moving on to their neighbors. It uses a FIFO queue: a node is enqueued when it is discovered and processed when it reaches the front of the queue. This produces a traversal that spreads outward in concentric "rings" or levels from the start node.

    BFS
          1. Start at A.
          2. Mark A as visited.
          3. Add A to the queue.
          4. Remove A from the queue.
          5. Visit B and C.
          6. Mark B and C as visited.
          7. Add B and C to the queue.
          8. Remove B from the queue.
          9. Visit D and E.
          10. Mark D and E as visited.
          11. Add D and E to the queue.
          12. Remove C from the queue.
          13. Visit F.
          14. Mark F as visited.
          15. Add F to the queue.
          16. Remove D, E, and F from the queue.
          17. Stop.

          BFS traversal: A → B → C → D → E → F.
    Time complexityO(V + E)
    Space complexityO(V)
    Data structureQueue (FIFO)
    Shortest path (unweighted)Guaranteed
    Shortest path in unweighted graphs Level-order traversal Web crawlers Peer-to-peer networking Social network "degrees of separation"
    DEPTH-FIRST SEARCH

    As deep as possible, then backtrack

    DFS starts at a source node and follows one path as far as it can go before backtracking to try another branch. It uses a LIFO stack — either explicit, or implicit through recursion. Each recursive call is one "push"; returning from it is a "pop" — the point where the algorithm backtracks to the previous node to try its next unvisited neighbor.

    DFS
        1. Start at A.
        2. Mark A as visited.
        3. Visit B.
        4. Mark B as visited.
        5. Visit D.
        6. Mark D as visited.
        7. D has no unvisited neighbors, so backtrack to B.
        8. Visit E.
        9. Mark E as visited.
        10. E has no unvisited neighbors, so backtrack to B.
        11. B has no more unvisited neighbors, so backtrack to A.
        12. Visit C.
        13. Mark C as visited.
        14. Visit F.
        15. Mark F as visited.
        16. F has no unvisited neighbors.
        17. Stop.

        DFS traversal: A → B → D → E → C → F
    Time complexityO(V + E)
    Space complexityO(V)
    Data structureStack (LIFO) / recursion
    Shortest path (unweighted)Not guaranteed
    Cycle detection Topological sorting Connected components Maze / puzzle solving Backtracking algorithms

    Handling cycles & disconnected graphs

    Cycles

    A traversal can revisit the same vertices indefinitely if it does not track which vertices have already been visited. The visited set/array prevents this: BFS only enqueues a newly discovered node, and DFS only explores a node that has not already been visited. Already-visited neighbors are simply left out of that step entirely. Build a graph with a cycle in the visualizer to see this directly — watch how the closing edge of the cycle never gets highlighted, because both of its endpoints are already visited by the time it's reached.

    Disconnected graphs

    A single BFS/DFS run only reaches the connected component containing the start node — nodes in a separate component are unreachable and stay unvisited. That's correct, expected behavior. In production code, a full traversal of every component loops over all vertices and starts a fresh BFS/DFS from any unvisited one. Build two separate clusters of nodes in the visualizer to see the run finish while nodes outside the reachable component stay in the default color.

    Project-defense guide

    Why is visited state necessary?

    Graphs can contain cycles and multiple paths to the same node. Marking a node visited prevents repeated processing and keeps the traversal finite.

    Why does BFS use a queue?

    FIFO ordering preserves discovery order. Nodes discovered earlier are processed before nodes discovered later, producing level-by-level exploration.

    Why does DFS backtrack?

    DFS keeps following an unvisited neighbor. When no deeper choice remains, it returns to the previous decision point and continues with another branch.

    Can traversal order change?

    Yes. The order of neighbors matters. GraphTrace uses a consistent neighbor ordering so the displayed result is deterministic for the same graph.

    What if the graph is disconnected?

    The current visualizer starts from the selected node and visits only the reachable component. Unvisited components remain untouched; a full-graph traversal would require starting another traversal from an unvisited node.

    What if the graph has a cycle?

    BFS and DFS still work because visited tracking prevents the same node from being processed repeatedly.

    Why does BFS find shortest paths in an unweighted graph?

    BFS explores by distance from the start: all nodes at distance 1 are reached before distance 2, then distance 3, and so on.

    Does DFS always find the shortest path?

    No. DFS is designed for depth-first exploration and does not guarantee the minimum number of edges to a target.

    ▶

    Which one should you use?

    Reach for BFS when…

    …you need the shortest path in an unweighted graph, you're exploring level-by-level (e.g. "friends of friends"), or the graph is very deep and you want to avoid a large recursion/stack depth.

    Reach for DFS when…

    …you need to explore every path fully (mazes, puzzles), detect cycles, compute a topological order, find connected components, or the graph is wide but shallow so a queue would balloon in size.

    ?

    Which traversal should I think about?

    BFS

    Think “layers”

    Use the BFS mental model when the problem is naturally organized by distance or levels from a source.

    • Queue / FIFO
    • Level-by-level
    • Shortest number of edges in unweighted graphs
    DFS

    Think “path”

    Use the DFS mental model when you need to explore deeply, search branches, or reason about backtracking.

    • Stack / recursion
    • Deep exploration
    • Backtracking and exhaustive exploration
    Important: BFS and DFS are both fundamental traversal strategies. The correct choice depends on the problem requirement; neither is universally “better.”
